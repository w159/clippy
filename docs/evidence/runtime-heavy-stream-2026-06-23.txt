## Original failing case (red state, from docs/.run/findings.json)

Symptom: the AI assistant locked Clippy up at ~100% CPU and ~2 GB RAM on a ~48.9 KB
streamed Ollama response (~64s), requiring force-quit. Spindump evidence:
- docs/evidence/spindump-2026-06-15-heaviest-stack.txt: Footprint 147 -> 2105 MB, 88% CPU,
  leaf SelectionOverlay.updateNSView (non-converging SwiftUI AttributeGraph loop).
- docs/evidence/spindump-2026-06-16-heaviest-stack.txt: Footprint 100 -> 1611 MB, 96% CPU,
  leaf SelectionOverlay.updateNSView -> setFont.

Root cause (verified 2026-06-17): .textSelection(.enabled) on the live-mutating streaming
Text caused a non-converging AttributeGraph update loop on the main thread. Fix removed
selection from the live branch (Sources/Clippy/AI/AIAssistantPanelView.swift). The 2026-06-17
run reproduced only a 1.6 KB / 60s stream (peak 9.3% CPU, RSS flat 314 MB); the >=40 KB
heavy case was NOT reproduced - that is the gap this evidence closes.

## Verdict

PASS (red -> green). The non-converging AttributeGraph loop signature - main thread
pinned at 88-96% with RSS climbing unbounded to 1.6-2.1 GB - does not reproduce under a
>=40 KB stream on the fixed binary. RSS stays flat at ~305-306 MB; CPU stays moderate
(10-38%, no sustained pin). The freeze fix is verified airtight for the heavy case that
the 2026-06-17 run could not reproduce.

Caveat: CPU averages ~17-28% during active streaming (higher than the 2026-06-17 1.6 KB
run's 9.3% peak), which is expected for rendering a long token stream and is not the
failure mode. The failure mode was sustained pin + unbounded growth, which is absent.
